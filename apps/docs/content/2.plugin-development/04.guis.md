The client side has started. The mod has a widget toolkit (`Label`, `Button`, `CheckBox`, `TextField`, `Slider`, `Gradient`, `ItemWidget`, `ScrollArea` and `ListView`, laid out on a `WidgetScreen`) that every SpoutCraft Redux screen is built from. Server-defined popups will render with the same widgets.

Popup GUIs are the heart of Spoutcraft: a plugin builds a screen out of widgets, and the client renders it as a native Minecraft screen with a cursor. Clicks, slider changes and text input go back to the server as events.

## Building a popup

```java
PopupScreen shop = Screens.popup()
    .add(Label.text(Component.text("Shop")).at(Anchor.TOP_CENTER, 0, 10))
    .add(Button.of(Component.text("Buy sword")).size(120, 20)
        .onClick(ctx -> ctx.player().give(sword)));

player.spoutCraftRedux().open(shop);
```

On a modded client this opens a real screen. On a vanilla client the server converts it into a [dialog](#vanilla-fallback).

## Widgets

The first release covers:

| Widget | Purpose |
|---|---|
| `Label` | Text, as an Adventure `Component` |
| `Texture` | An image, sent as a hash-checked runtime asset |
| `Rect` / `Gradient` | Solid or gradient rectangles |
| `Button` | Clickable button with a callback |
| `TextField` | Single-line text input |
| `Slider` | Numeric range |
| `CheckBox` | Boolean toggle |
| `ItemWidget` | Renders an item stack |
| `Container` | Groups children in a row, a column, or absolute positions |

Later releases add `ComboBox`, list and scroll areas, `EntityWidget`, inventory slots and animations.

Every widget has a position, an anchor (such as `TOP_LEFT` or `CENTER`), a size, a colour and an optional tooltip.

## Screen kinds

| Kind | Behaviour |
|---|---|
| `POPUP` | A modal screen with a cursor |
| `OVERLAY` | Drawn over the current vanilla screen |
| `HUD` | An overlay without input; see [HUD](/plugin-development/hud) |

## Events

Widget callbacks such as `onClick` run on the server. The same actions also fire Bukkit events, so other plugins can listen:

- `SpoutCraftReduxButtonClickEvent`
- `SpoutCraftReduxSliderChangeEvent`
- `SpoutCraftReduxTextSubmitEvent`
- `SpoutCraftReduxScreenCloseEvent`

The server checks that every incoming event refers to a widget that exists and is interactive before firing anything.

## Updating a screen

The server keeps the widget tree for each player and screen, and sends only diffs: adding, changing or removing a single widget. Changing a label's text on an open screen sends one small update, not the whole screen.

## Vanilla fallback

For vanilla clients the server turns a popup into a vanilla **dialog**:

| Widget | Dialog element |
|---|---|
| `Button` | Action button (`multi_action`) |
| `TextField` | Text input |
| `CheckBox` | Boolean input |
| `Slider` | Number range |
| `Label` | Body text |

When a screen contains a widget that has no dialog equivalent, the plugin can supply its own fallback handler, for example to open a chest menu instead.
