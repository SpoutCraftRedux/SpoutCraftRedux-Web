Custom items are real items. The server adds them to Minecraft's item registry next to the vanilla ones, and the client mod adds the same items when a player joins. `/give`, inventories, crafting, stacking and saving all treat them like any other item.

Players need the client mod to join a server with custom items. Without it they are disconnected while joining; see [players without the client](/plugin-development/players-without-the-client#servers-with-custom-items).

## Registering items

Items are registered from a [bootstrapper](https://docs.papermc.io/paper/dev/getting-started/paper-plugins/#bootstrapper), which runs before the server's registries are locked. Registering later throws `IllegalStateException`.

```yaml [paper-plugin.yml]
name: MyPlugin
main: com.example.MyPlugin
bootstrapper: com.example.MyPluginBootstrap
```

```java
public class MyPluginBootstrap implements PluginBootstrap {
    public static final Key RUBY = Key.key("myplugin", "ruby");

    @Override
    public void bootstrap(BootstrapContext context) {
        SpoutCraftRedux.content().registerItem(CustomItem.builder(RUBY)
            .name(Component.text("Ruby"))
            .rarity(ItemRarity.UNCOMMON)
            .build());
    }
}
```

The id can use any namespace except `minecraft`.

## Models

An item uses the model `assets/<namespace>/items/<path>.json` from the [server resource pack](/plugin-development/images-and-resource-packs#resource-packs), the same format as vanilla item models. Ship it in your plugin's pack:

```json [assets/myplugin/items/ruby.json]
{ "model": { "type": "minecraft:model", "model": "myplugin:item/ruby" } }
```

```json [assets/myplugin/models/item/ruby.json]
{ "parent": "minecraft:item/generated", "textures": { "layer0": "myplugin:item/ruby" } }
```

The texture goes in `assets/myplugin/textures/item/ruby.png`. Use `.model(Key)` to point at a different model.

## Builder options

::field-group
  :::field{name="name(Component)" type="Builder"}
  The default name. Defaults to the id's path.
  :::

  :::field{name="model(Key)" type="Builder"}
  The item model. Defaults to the item id.
  :::

  :::field{name="maxStackSize(int)" type="Builder"}
  1 to 99. Defaults to 64.
  :::

  :::field{name="maxDamage(int)" type="Builder"}
  Durability. The item then stacks to 1. It also replaces a tool's or armor's own durability.
  :::

  :::field{name="rarity(ItemRarity)" type="Builder"}
  Colors the name.
  :::

  :::field{name="fireResistant(boolean)" type="Builder"}
  Dropped items survive fire and lava.
  :::

  :::field{name="food(int nutrition, float saturation, boolean canAlwaysEat)" type="Builder"}
  Makes the item edible. `saturation` is the modifier, as in vanilla: bread is 5 and 0.6.
  :::

  :::field{name="tool(ToolType, ToolMaterial, float attackDamage, float attackSpeed)" type="Builder"}
  A sword, pickaxe, axe, shovel or hoe with a vanilla tier's mining speed, durability, enchantability and repair items. Axes strip logs, shovels make paths and hoes till, as in vanilla. The attack numbers are the baselines vanilla passes for its own tools: a diamond sword is 3 and -2.4.
  :::

  :::field{name="armor(ArmorMaterial, ArmorPiece[, Key equipmentAsset])" type="Builder"}
  Armor with a vanilla material's defense, toughness and durability. Without an equipment asset it looks like that material when worn.
  :::

  :::field{name="equippable(EquipmentSlot)" type="Builder"}
  Lets players wear an item that isn't armor, such as a hat on `HEAD`.
  :::

  :::field{name="onUse(UseHandler)" type="Builder"}
  Called when a player right-clicks with the item in the air. Return `true` if it did something.
  :::

  :::field{name="onUseOnBlock(UseOnBlockHandler)" type="Builder"}
  Called when a player right-clicks a block with the item. Return `true` if it did something.
  :::
::

```java
SpoutCraftRedux.content().registerItem(CustomItem.builder(Key.key("myplugin", "ruby_sword"))
    .name(Component.text("Ruby Sword"))
    .tool(CustomItem.ToolType.SWORD, CustomItem.ToolMaterial.DIAMOND, 4, -2.4f)
    .build());

SpoutCraftRedux.content().registerItem(CustomItem.builder(Key.key("myplugin", "lightning_wand"))
    .name(Component.text("Lightning Wand"))
    .maxDamage(32)
    .onUseOnBlock((player, hand, item, block, face) -> {
        block.getWorld().strikeLightningEffect(block.getRelative(face).getLocation());
        item.damage(1, player);
        return true;
    })
    .build());
```

## Worn looks

To give armor its own look, pass an equipment asset and ship it in the pack, the same way vanilla defines armor:

```java
.armor(CustomItem.ArmorMaterial.DIAMOND, CustomItem.ArmorPiece.HELMET, Key.key("myplugin", "ruby"))
```

```json [assets/myplugin/equipment/ruby.json]
{ "layers": { "humanoid": [ { "texture": "myplugin:ruby" } ] } }
```

The texture goes in `assets/myplugin/textures/entity/equipment/humanoid/ruby.png`, laid out like vanilla's armor textures.

## Using items in code

`SpoutCraftRedux.content()` returns the server's `ContentRegistry`:

::field-group
  :::field{name="createStack(CustomItem, int amount)" type="ItemStack"}
  A new stack. Works once the server has started.
  :::

  :::field{name="item(ItemStack)" type="CustomItem"}
  The custom item a stack is, or `null`.
  :::

  :::field{name="item(Key id)" type="CustomItem"}
  The custom item with that id, or `null`.
  :::

  :::field{name="items()" type="Collection<CustomItem>"}
  Every custom item, in registration order.
  :::
::

```java
CustomItem ruby = SpoutCraftRedux.content().item(MyPluginBootstrap.RUBY);
player.getInventory().addItem(SpoutCraftRedux.content().createStack(ruby, 3));
```

Bukkit's `Material` enum only lists vanilla items, so `getType()` on a custom stack returns `Material.SPOUTCRAFTREDUX_CUSTOM_ITEM` for every custom item. Use `content().item(stack)` to tell them apart, and read stack sizes and durability from the `ItemStack` rather than the material. A stack can't be created from that material.
