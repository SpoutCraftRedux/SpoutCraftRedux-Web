A plugin registers key bindings with the server. Players with the client mod see them under **Custom Bindings** in the [Controls screen](/getting-started/controls-and-shortcuts), can rebind them, and send a press event back to the server.

## Registering a binding

```java
@Override
public void onEnable() {
    SpoutCraftRedux.keyBindings().register(this, KeyBinding.of(
        Key.key("myplugin", "open_menu"),
        Component.text("Open menu"),
        "key.keyboard.m"
    ));
}
```

`SpoutCraftRedux.keyBindings()` returns the server's `KeyBindingRegistry`:

::field-group
  :::field{name="register(Plugin, KeyBinding)" type="void"}
  Adds a binding. A binding with the same id replaces the old one.
  :::

  :::field{name="unregister(Key id)" type="void"}
  Removes one binding.
  :::

  :::field{name="unregisterAll(Plugin)" type="void"}
  Removes every binding the plugin registered.
  :::

  :::field{name="get(Key id)" type="KeyBinding"}
  The binding with that id, or `null`.
  :::

  :::field{name="all()" type="Collection<KeyBinding>"}
  Every binding, in registration order.
  :::
::

Changes go out straight away to every online player with the client. When a plugin is disabled, its bindings are dropped automatically. The registry is found through Java's `ServiceLoader`, so you can register in `onEnable` even with `load: STARTUP`.

## The binding

`KeyBinding` is a record of `(Key id, Component name, @Nullable String defaultKey, Set<KeyModifier> defaultModifiers)`:

- **id**: unique, in your plugin's namespace, such as `myplugin:open_menu`
- **name**: shown in the Controls screen, with your plugin's name on a second line
- **defaultKey**: Minecraft's name for the key, `key.keyboard.<name>` or `key.mouse.<name>` (for example `key.keyboard.m` or `key.mouse.middle`), or `null` for no default. Anything else throws `IllegalArgumentException`.
- **defaultModifiers**: `KeyModifier.CTRL`, `SHIFT` and `ALT`, which must be held with the default key. `CTRL` means Cmd on macOS.

```java
KeyBinding.of(Key.key("myplugin", "quick_save"), Component.text("Quick save"),
    "key.keyboard.s", KeyModifier.CTRL, KeyModifier.SHIFT);
```

## Presses

Each press fires `SpoutCraftReduxKeyBindingEvent`, and each release fires it again. It extends `PlayerEvent`:

```java
@EventHandler
public void onKey(SpoutCraftReduxKeyBindingEvent event) {
    if (event.isPressed() && event.getKeyBinding().id().equals(Key.key("myplugin", "open_menu"))) {
        openMenu(event.getPlayer());
    }
}
```

The client only sends presses while the player has no screen open, and only for bindings the server registered. It never forwards raw keyboard input.

## What the player sees

- Server bindings appear under Custom Bindings as blue rows marked "B".
- Players can rebind them, with modifiers, or unbind them with Delete.
- Their choices are saved per server address, or as "singleplayer", in `config/spoutcraftredux/server_bindings.json`. Only changed bindings are stored.
- Two bindings are only marked red when each one counts the other as a conflict, so a server binding on H isn't red against Minecraft's F3+H.

## Players without the client

Players without the mod never send presses. Offer a command or an item as an alternative for them.

## Protocol

Clients that support server bindings report `keybind.v1`.

| Channel | Direction | Contents |
|---|---|---|
| `spoutcraftredux:key_bindings` | Server to client | The full list each time, at most 256: id, name as JSON, plugin name, default key name, modifier bits (CTRL = 1, SHIFT = 2, ALT = 4) |
| `spoutcraftredux:key_binding_pressed` | Client to server | The id and whether it was pressed or released |
