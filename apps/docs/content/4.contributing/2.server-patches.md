The server is a fork of Purpur, which is itself a fork of Paper. SpoutCraft Redux keeps its changes as a stack of patches on top of Purpur, managed by [paperweight](https://github.com/PaperMC/paperweight). Keeping patches small is what makes upstream updates cheap.

## Where code goes

- **New code** goes in new files under `spoutcraftredux-server/src/main/java` and `spoutcraftredux-api/src/main/java`, in the `org.spoutcraftredux` package. Most work happens here.
- **Patches** only add **hooks** into Minecraft, Paper or Purpur: a few lines that call into the new code.

Mark patched lines so they are easy to find during updates. For example:

```java
// SpoutCraft Redux start - configuration-phase handshake
SpoutCraftReduxServer.addHandshakeTask(this);
// SpoutCraft Redux end
```

Keep **one patch per feature**, so a patch that breaks during an update can be dropped and redone on its own. Add API through new files in `spoutcraftredux-api` whenever possible; API patches should only add accessors such as `Player#spoutCraftRedux()`.

## Changing a patch

::steps{level="3"}

### Apply the patches

```bash [Terminal]
./gradlew applyAllPatches
```

### Edit the applied sources

Make your change in the generated source trees, such as `spoutcraftredux-server/src/minecraft/java`, `paper-server` or `paper-api`.

### Commit inside that folder

Each applied source tree is its own Git repository. Commit your change there.

### Rebuild the patches

```bash [Terminal]
./gradlew rebuildAllServerPatches
```

Use `rebuildPaperApiPatches` for API changes.

### Commit the patch files

Commit the resulting `.patch` files in the main repository. The patches are what gets reviewed and shipped, not the applied sources.

::

## Updating Purpur

::steps{level="3"}

### Bump the commit

Set `purpurCommit` in `server/gradle.properties` to the new Purpur commit.

### Reapply

```bash [Terminal]
./gradlew applyAllPatches
```

### Fix conflicts and rebuild

Resolve any patches that fail to apply, then run `./gradlew rebuildAllServerPatches` and commit.

::

::note
CI fails when the committed patches are out of date, so always rebuild patches before opening a pull request.
::
