Every `Player` on a SpoutCraft Redux server has a `SpoutCraftReduxPlayer` view, whether or not they run the client mod:

```java
SpoutCraftReduxPlayer scr = player.spoutCraftRedux();
```

The view is the entry point for all per-player features. You can call it for any player; client features simply do nothing for players without the client. See [players without the client](/plugin-development/players-without-the-client).

## Available now

::field-group
  :::field{name="getPlayer()" type="Player"}
  The Bukkit player this view belongs to.
  :::

  :::field{name="isModded()" type="boolean"}
  Whether the player completed the SpoutCraft Redux handshake during login.
  :::

  :::field{name="protocolVersion()" type="int"}
  The negotiated protocol version, or `0` for vanilla clients.
  :::

  :::field{name="capabilities()" type="Set<String>"}
  The features the client reported, such as `ui.v1` or `sky.v1`. Empty for vanilla clients.
  :::

  :::field{name="hasCapability(String)" type="boolean"}
  Shortcut for `capabilities().contains(...)`.
  :::

  :::field{name="modVersion()" type="Optional<String>"}
  The client mod's version string, if the player is modded.
  :::

  :::field{name="movement()" type="MovementModifiers"}
  Gravity, walking and jumping multipliers. See [Movement](/plugin-development/movement).
  :::

  :::field{name="openScreen(PopupScreen)" type="void"}
  Opens a popup screen. `getOpenScreen()` and `closeScreen()` go with it. See [GUIs](/plugin-development/guis).
  :::

  :::field{name="hud()" type="Hud"}
  The player's HUD, which you attach widgets to. See [HUD](/plugin-development/hud).
  :::

  :::field{name="sendNotification(Component, Component, ItemStack)" type="void"}
  Shows a popup with a title, a message and an item icon to players with the client. An overload takes a `Duration`. See [Notifications](/plugin-development/notifications).
  :::
::

```java
SpoutCraftReduxPlayer scr = player.spoutCraftRedux();
if (scr.hasCapability("sky.v1")) {
    // client can render custom skies
}
```

::warning
`isModded()` and the capability set come from the client, and the client is untrusted. Use them to decide **what to send**, never to grant permissions or skip checks.
::

## Handshake events

The handshake runs during the login configuration phase, before the player enters the world. Exactly one of these events fires for each player, just before `PlayerJoinEvent`:

| Event | Fires when |
|---|---|
| `SpoutCraftReduxClientReadyEvent` | The client mod answered the handshake. `getSpoutCraftReduxPlayer()` returns the populated view. |
| `SpoutCraftReduxClientMissingEvent` | No answer arrived within `handshake.timeout-ticks`, or the client reported the vanilla brand. `getMessage()` and `setMessage(Component)` change or remove (with `null`) the [download message](/plugin-development/players-without-the-client#the-download-message) the player gets. |

Both live in `org.spoutcraftredux.api.event` and extend `PlayerEvent`.

```java
@EventHandler
public void onReady(SpoutCraftReduxClientReadyEvent event) {
    var scr = event.getSpoutCraftReduxPlayer();
    getLogger().info(event.getPlayer().getName() + " uses protocol " + scr.protocolVersion());
}
```

## Capabilities

Features are gated on capability strings, not on the protocol version, so the client and server can update separately. The client reports `notification.v1`, `keybind.v1`, `ui.v1`, `hud.v1` and `asset.v1` today. The rest are planned:

| Capability | Feature |
|---|---|
| `ui.v1` | [Popup GUIs](/plugin-development/guis) |
| `hud.v1` | [HUD widgets](/plugin-development/hud) |
| `sky.v1` | [Sky and environment](/plugin-development/sky) |
| `keybind.v1` | [Key bindings](/plugin-development/keybinds) |
| `notification.v1` | [Notifications](/plugin-development/notifications) |
| `asset.v1` | [Images](/plugin-development/images-and-resource-packs) |
| `cape.v1` | [Capes](/plugin-development/capes) |
| `block.v1` | Custom blocks |

In most cases you do not need to check them yourself: the feature APIs pick the modded or vanilla path for you.
