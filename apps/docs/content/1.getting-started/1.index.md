SpoutCraft Redux is a remake of **Spoutcraft** for modern Minecraft Java Edition. The original Spoutcraft (2011–2014) was a client mod and Bukkit plugin pair. It let a server push custom GUIs, HUD widgets, textures, sounds, sky settings, keybinds and movement rules to every connected player, without asking them to install anything server-specific.

SpoutCraft Redux brings that idea to **Minecraft 26.3** on **Java 25**.

## How it fits together

SpoutCraft Redux has two halves that talk to each other over vanilla custom payloads on the `spoutcraftredux:` namespace.

Plugins compile against `spoutcraftredux-api`, which is the Purpur API plus the `org.spoutcraftredux.api` package. See [Plugin Development](/plugin-development).

## Players without the client

Players without the client mod can still join a SpoutCraft Redux server like any other Purpur server. The server waits briefly for the SpoutCraft Redux handshake during login, and when no answer arrives it treats the player as vanilla.

Like the original Spoutcraft, client features such as popups, the HUD, notifications and key bindings do nothing for those players. Instead, the server sends them a chat message with a link to download the client. Features built on vanilla mechanics, such as movement and the server resource pack, still work for everyone. See [players without the client](/plugin-development/players-without-the-client).

## Data, never code

The server only ever sends **descriptions**: widget trees, sky parameters, keybind declarations and asset hashes. It never sends classes or scripts to the client. Runtime images are checked against their SHA-256 hash and size-limited. The client only reads the clipboard or takes a screenshot for a server after asking the player, and never opens URLs on the server's behalf without asking. Server-pushed addons are planned for later, and will need code signing and the player's confirmation.

## What works today

- The server fork builds and runs as a drop-in Purpur replacement.
- The client mod and server complete a versioned capability handshake during login.
- `SpoutCraftReduxClientReadyEvent` and `SpoutCraftReduxClientMissingEvent` fire before `PlayerJoinEvent`.
- `player.spoutCraftRedux()` reports whether a player is modded, their protocol version, capabilities and mod version.
- `/spoutcraftredux list` shows which online players run the mod.
- Plugins can show [notifications](/plugin-development/notifications) to players with the client.
- Plugins can change a player's gravity, walking speed and jump strength through [movement multipliers](/plugin-development/movement).
- Plugins can open [popup screens](/plugin-development/guis) and draw [HUD widgets](/plugin-development/hud) built from server-side widgets.
- Plugins can hide and move Minecraft's own [HUD elements](/plugin-development/hud#vanilla-hud-elements), such as health, the hotbar or chat.
- Plugins can register [images and add a resource pack](/plugin-development/images-and-resource-packs); the merged pack goes to every player, so custom sounds and models work for vanilla players too.
- The client replaces Minecraft's key binds screen with a [Controls screen](/getting-started/controls-and-shortcuts) that supports modifier keys, shows conflicts and has player-made shortcuts.
- Plugins can register [key bindings](/plugin-development/keybinds) that players see and rebind under Custom Bindings.

Pages in this documentation mark unfinished features with a **Planned** badge. The code samples on those pages show the intended API shape, not something you can call yet.

## Not planned

Every player-facing feature of the original is in scope. Only two are dropped: the chunk network cache and the packet interception API.
