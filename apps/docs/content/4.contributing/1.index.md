The SpoutCraft Redux source lives on [GitHub](https://github.com/SpoutCraftRedux). The main repository holds three separate Gradle builds, each with its own wrapper.

| Folder | What it builds | Command |
|---|---|---|
| `protocol/` | The shared wire format and its tests | `./gradlew test` |
| `client/` | The Fabric client mod | `./gradlew build`, output in `build/libs/` |
| `server/` | The Purpur fork (paperweight-patcher) | `./gradlew applyAllPatches`, then `./gradlew createMojmapPaperclipJar` |

## Requirements

- **Java 25**
- **Git.** The server build has two extra rules:
  - It must run inside a Git clone, because paperweight uses Git to apply patches.
  - The jar tasks need at least one commit, because they stamp the commit hash into the jar.

## Try it locally

::steps{level="3"}

### Start the server

```bash [Terminal]
cd server
./gradlew applyAllPatches
./gradlew runDevServer
```

The dev server runs from `server/run/`.

### Allow offline accounts

Dev clients use offline accounts. In `server/run/server.properties`, set:

```properties [server.properties]
online-mode=false
white-list=false
```

### Start the client

```bash [Terminal]
cd client
./gradlew runJoinLocal
```

This launches the game with the mod and joins `localhost:25565`.

### Check the handshake

Run `/spoutcraftredux list` on the server. Each player shows as SpoutCraft Redux or vanilla.

::

### Test plugin

The server build includes an optional test plugin. It logs the SpoutCraft Redux join events and sends each player a notification shortly after they join. It also:

- shows a HUD with a "Mana" label and bar in the top left
- registers a key binding on H (`spoutcraftredux_test:hello`) that opens a test popup with an image, a button, a checkbox, a text field, a slider, a list and a Close button, and logs every interaction
- adds a resource pack that turns the diamond into a red gem, which you can see in the welcome notification
- opens a demo shop, "Emerald Emporium", on J: a grid of item tiles, a detail pane and styled Buy buttons that grey out when you can't afford an item, paid for in emeralds checked on the server

 To enable it, create `server/test-plugin.settings.gradle.kts`:

```kotlin [test-plugin.settings.gradle.kts]
include(":test-plugin")
```

### Widget demo

In a dev client (`runClient` or `runJoinLocal`), `/spoutcraftredux-client widgets` opens a screen with every widget in the toolkit. The command only exists in dev runs.

### Input on 26.3

Minecraft 26.3 moved input to SDL, which changes a few things for client code:

- The left mouse button is `InputConstants.MOUSE_BUTTON_LEFT`, which is `1`, not `0`.
- Typed characters only arrive while `minecraft.onTextInputFocusChange(listener, true)` is on.
- Key codes are SDL scancodes.

### Client mixins

The Controls screen and modifier keys use four mixins and one accessor:

| Class | Target | Why |
|---|---|---|
| `GuiMixin` | `Gui.setScreen` | Opens the Controls screen instead of Minecraft's key binds screen |
| `KeyMappingMixin` | `KeyMapping.setDown` and its click lambda | Only lets a binding fire while its modifiers are held |
| `KeyboardHandlerMixin` | `KeyboardHandler.keyPress` and `handleDebugKeys` | Standalone F3 keys and modifier tracking |
| `MouseHandlerMixin` | `MouseHandler.onButton` | Modifiers on mouse button bindings |
| `OptionsSubScreenAccessor` | `OptionsSubScreen.lastScreen` | Gives the Controls screen the screen to go back to |

## Repository layout

```text
SpoutCraftRedux/
├─ protocol/                 # message records and codecs, no Minecraft dependency
├─ server/                   # paperweight-patcher build
│  ├─ spoutcraftredux-api/     # public plugin API
│  ├─ spoutcraftredux-server/  # server implementation and patches
│  └─ test-plugin/
└─ client/                   # Fabric mod (Loom)
```

The `protocol` module is plain Java 25 and is included by both the client and server builds, so the wire format is defined once.
