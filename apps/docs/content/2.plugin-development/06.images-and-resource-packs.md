`SpoutCraftRedux.assets()` returns the server's `AssetRegistry` (package `org.spoutcraftredux.api.asset`). Like `keyBindings()`, it is found through Java's `ServiceLoader`, so you can use it in `onEnable`.

```java
AssetRegistry assets = SpoutCraftRedux.assets();
Asset logo = assets.registerImage(this, Key.key("myplugin", "logo"), "images/logo.png");
assets.addResourcePack(this, "resourcepack");

screen.attach(new Texture(logo).setGeometry(5, 5, 64, 32));
```

## Images

| Method | Returns |
|---|---|
| `registerImage(plugin, Key id, String path)` | Reads a PNG from your plugin jar and registers it |
| `registerImage(plugin, Key id, byte[] png)` | Registers PNG bytes |
| `get(Key id)` | The registered `Asset`, or `null` |

Both `registerImage` methods return an `Asset` record of `(Key id, String sha256, int size)`.

- **Format and size:** images must be PNG files of at most 4 MiB. Anything else throws `IllegalArgumentException`.
- **Dimensions:** the client also refuses images larger than 2048×2048.

### Showing an image

Use a `Texture` widget on a [popup](/plugin-development/guis) or the [HUD](/plugin-development/hud). The image is stretched to the widget's size.

- **Size:** a texture has no natural size, so always give it a width and height.
- **Loading:** it draws nothing until the image has arrived.

### How images reach the client

- **On demand:** the client only fetches an image when a `Texture` widget shows it.
- **Request:** it asks with `spoutcraftredux:asset_request`, sending the image's SHA-256.
- **Answer:** the server replies with `spoutcraftredux:asset_data` in 512 KiB pieces. It only answers for images that are registered.
- **Checking and caching:** the client checks the SHA-256 before using the file. It then caches it in `<game folder>/spoutcraftredux/cache/<sha256>.png`, so each image downloads once across all servers.

Clients that support this report `asset.v1`.

## Resource packs

| Method | Adds |
|---|---|
| `addResourcePack(plugin, String folder)` | A folder inside your plugin jar, laid out like a pack (`assets/<namespace>/...`) |
| `addResourcePack(plugin, Path path)` | A zip or folder on disk |

The server merges every plugin's files into one pack:
- **Same path:** a later plugin's file replaces an earlier one with the same path.
- **`pack.mcmeta`:** yours is ignored. The server writes its own for pack format 97 (Minecraft 26.3).
- **Unsafe paths:** paths that contain `..` are dropped.

### Players get it on join

- **Who gets it:** the merged pack goes to every player when they join, with or without the client mod. It is sent through Paper's `sendResourcePacks`.
- **What works for vanilla players:** custom sounds, item models, textures, fonts and languages from the pack all work for vanilla players too. For example, play a pack sound with Paper's normal API:

```java
player.playSound(player.getLocation(), "myplugin:shop.open", 1.0f, 1.0f);
```

### Hosting

The server hands out the pack from a small built-in web server:

```text
http://<the address the player joined with>:<resource-pack.port>/pack/<sha1>.zip
```

Every other path returns 404. Open the port in your firewall. Behind a proxy or CDN, set `resource-pack.public-url` and the pack URL becomes `<public-url>/pack/<sha1>.zip`. See [the server settings](/getting-started/installing-the-server#configuration).
