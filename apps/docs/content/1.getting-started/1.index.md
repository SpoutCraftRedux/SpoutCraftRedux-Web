SpoutCraft Redux is a remake of **Spoutcraft** for modern Minecraft Java Edition. The original Spoutcraft (2011–2014) was a client mod and Bukkit plugin pair. It let a server push custom GUIs, HUD widgets, textures, sounds, sky settings, keybinds and movement rules to every connected player, without asking them to install anything server-specific.

SpoutCraft Redux brings that idea to **Minecraft 26.3** on **Java 25**.

## How it fits together

SpoutCraft Redux has two halves that talk to each other over vanilla custom payloads on the `spoutcraftredux:` namespace.

::card-group
  :::card
  ---

  ---
  A fork of [Purpur](https://purpurmc.org) (Paper → Purpur → SpoutCraft Redux), shipped as a paperclip jar. It is a drop-in replacement for the Purpur jar, so existing Paper and Purpur plugins keep working.
  :::

  :::card
  ---
  icon: i-lucide-monitor
  title: Client
  to: /getting-started/installing-the-client
  ---
  A [Fabric](https://fabricmc.net) mod. It answers the server's handshake and renders whatever the server describes: widgets, HUD layers, sky, keybinds. A NeoForge version is planned for later.
  :::
::

Plugins compile against `spoutcraftredux-api`, which is the Purpur API plus the `org.spoutcraftredux.api` package. See [Plugin Development](/plugin-development).

## Vanilla players

The client mod is optional. Players without it join a SpoutCraft Redux server like any other Purpur server. The server waits briefly for the SpoutCraft Redux handshake during login, and when no answer arrives it treats the player as vanilla.

Every feature in the API defines what a vanilla client gets instead. A popup GUI can become a vanilla dialog, a HUD label can fall back to the action bar, and movement changes use vanilla attributes, so they work for everyone. Some features, such as custom sky colours, have no vanilla equivalent and are skipped. The [vanilla fallback](/plugin-development/vanilla-fallback) page lists the behaviour for each feature.

## Data, never code

The server only ever sends **descriptions**: widget trees, sky parameters, keybind declarations and asset hashes. It never sends classes or scripts to the client. Runtime images are checked against their SHA-256 hash and size-limited, and the client never reads the clipboard, takes screenshots or opens arbitrary URLs on the server's behalf.

## Project status

::warning
SpoutCraft Redux is in **Phase 0**: the protocol, client and server skeletons are in place. It is not ready for production servers yet, and the API will change before the first `0.x` freeze.
::

What works today:

- The server fork builds and runs as a drop-in Purpur replacement.
- The client mod and server complete a versioned capability handshake during login.
- `SpoutCraftReduxClientReadyEvent` and `SpoutCraftReduxClientMissingEvent` fire before `PlayerJoinEvent`.
- `player.spoutCraftRedux()` reports whether a player is modded, their protocol version, capabilities and mod version.
- `/spoutcraftredux list` shows which online players run the mod.

What comes next, roughly in order:

| Phase | Focus |
|---|---|
| 1 | Movement, floating text, sounds, toasts and keybinds, with vanilla parity where possible |
| 2 | The widget system: popup GUIs, HUD overlays, hiding and moving vanilla HUD bars |
| 3 | Sky and fog, a generated resource pack, sounds from the pack, capes and nameplates |
| 4 | Custom items, recipes and enchantments, Javadoc and a first API freeze |
| 5 | Custom blocks |
| 6 | NeoForge client, Minecraft 26.4, minimap integrations |

Pages in this documentation mark unfinished features with a **Planned** badge. The code samples on those pages show the intended API shape, not something you can call yet.

## Not planned

Some original Spoutcraft features stay out on purpose: a built-in minimap (integrate with Xaero's or JourneyMap instead), the chunk network cache, client addons that run server-supplied code, clipboard sync and silent screenshots.
