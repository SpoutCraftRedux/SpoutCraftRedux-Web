A plugin builds a screen out of widgets on the server, and players with the client mod see it as a native Minecraft screen with a cursor. Clicks, typing, slider drags and list selection come back to the server as callbacks.

Everything lives in `org.spoutcraftredux.api.gui`.

## Opening a popup

```java
PopupScreen shop = new PopupScreen(Component.text("Shop"));

Label status = new Label(Component.text("Pick something"))
    .setAnchor(WidgetAnchor.TOP_CENTER).setGeometry(0, 20, 0, 0)
    .setAlign(TextAlign.CENTER);

Button buy = new Button(Component.text("Buy an emerald"))
    .setAnchor(WidgetAnchor.CENTER_CENTER).setGeometry(-100, -10, 200, 20)
    .onClick(p -> {
        p.getInventory().addItem(ItemStack.of(Material.EMERALD));
        status.setText(Component.text("Thanks!"));
    });

shop.attach(status, buy);
player.spoutCraftRedux().openScreen(shop);
```

Changing a widget that's already on screen, like `status.setText(...)` above, updates it for the player straight away.

### The screen

`new PopupScreen(Component title)` creates an empty screen.

| Method | What it does |
|---|---|
| `attach(widgets...)` | Adds widgets. They're drawn in the order you attach them. |
| `detach(widget)` | Removes one widget. |
| `onClose(Consumer<Player>)` | Runs when the player closes the screen, for example with Escape. |
| `close()` | Closes it for whoever has it open. |

On `SpoutCraftReduxPlayer`:

| Method | What it does |
|---|---|
| `openScreen(PopupScreen)` | Opens the screen. It replaces any popup opened before. |
| `getOpenScreen()` | The popup the player has open, or `null`. |
| `closeScreen()` | Closes it. |

The game keeps running while a popup is open; nothing is paused.

## Placing widgets

Every widget extends `Widget<T>`, so the setters chain.

| Method | Meaning |
|---|---|
| `setGeometry(x, y, width, height)` | Position and size in one call |
| `setX`, `setY`, `setWidth`, `setHeight` | One value at a time |
| `setAnchor(WidgetAnchor)` | The point on the screen that `x` and `y` count from. The default is `TOP_LEFT`. |
| `setVisible(boolean)` | Hides or shows it |
| `setEnabled(boolean)` | A disabled widget is greyed out and takes no input |
| `setTooltip(Component)` | Text shown on hover |

A width or height of `0` keeps the widget's natural size, such as 200×20 for a button or 16×16 for an item.

### Anchors

`WidgetAnchor` is one of `TOP_LEFT`, `TOP_CENTER`, `TOP_RIGHT`, `CENTER_LEFT`, `CENTER_CENTER`, `CENTER_RIGHT`, `BOTTOM_LEFT`, `BOTTOM_CENTER`, `BOTTOM_RIGHT` or `SCALE`.

- With the first nine, `x` and `y` are offsets from that point on the screen, so `CENTER_CENTER` with `x = -100` puts a 200-wide button in the middle.
- `SCALE` puts position and size on a 427×240 layout that stretches to fill the screen.

## Widgets

| Widget | Properties | Callback |
|---|---|---|
| `Label` | text, color (ARGB, default white), shadow (default on), wrap, align | |
| `Button` | text, align | `onClick(Consumer<Player>)` |
| `CheckBox` | text, checked | `onChange(BiConsumer<Player, Boolean>)` |
| `TextField` | text, placeholder, maxLength (1 to 4096, default 256) | `onChange` while typing, `onSubmit` on Enter, both `BiConsumer<Player, String>` |
| `Slider` | text, position (0 to 1) | `onChange(BiConsumer<Player, Float>)` |
| `Gradient` | top and bottom ARGB colors | |
| `ItemWidget` | an `ItemType`, such as `new ItemWidget(ItemType.EMERALD)` | |
| `ListWidget` | rows (`ListWidget.Row(title, text)`), selected index (`-1` for none) | `onSelect(BiConsumer<Player, Integer>)` |
| `Texture` | an image [registered with the server](/plugin-development/images-and-resource-packs) | |

`TextAlign` (`LEFT`, `CENTER`, `RIGHT`) sets the text alignment of labels and buttons.

A slider can show its own value by updating its text from `onChange`:

```java
Slider volume = new Slider(Component.text("Volume: 50%")).setPosition(0.5f);
volume.onChange((p, pos) -> volume.setText(Component.text("Volume: " + Math.round(pos * 100) + "%")));
```

Updates from the server change widgets in place, so they don't interrupt a player who is dragging a slider or typing in a field.

### Styling buttons

By default a button looks like a vanilla Minecraft button. You can style it per `ButtonState`: `NORMAL`, `HOVER` or `DISABLED`. Anything you don't set for `HOVER` or `DISABLED` uses the `NORMAL` style.

| Method | What it does |
|---|---|
| `setTexture(ButtonState, Asset)` | Draws an [image registered with the server](/plugin-development/images-and-resource-packs) as the button. `setTexture(Asset)` sets `NORMAL` only; `null` removes it. |
| `setTextureBorder(int)` | Nine-slices the image: that many image pixels at each edge stay unstretched, so the corners stay sharp. `0`, the default, stretches the whole image. |
| `setBackground(ButtonState, Integer argb)` | Draws a flat colour instead of the vanilla texture. An image takes priority over a colour. |
| `setTextColor(ButtonState, Integer argb)` | The text colour for that state. Colours inside the label `Component` still take priority. |
| `setTextShadow(boolean)` | Turns the text shadow on or off. It's on by default. |

`getTexture`, `getTextureBorder`, `getBackground`, `getTextColor` and `hasTextShadow` read the values back. Until an image has downloaded, the player sees the vanilla button.

```java
Button buy = new Button(Component.text("Buy"))
    .setTexture(ButtonState.NORMAL, gold)
    .setTexture(ButtonState.HOVER, goldHover)
    .setTexture(ButtonState.DISABLED, goldGrey)
    .setTextureBorder(3)
    .setTextShadow(false)
    .setTextColor(ButtonState.NORMAL, 0xFF3A2508);

Button close = new Button(Component.text("Close"))
    .setBackground(ButtonState.NORMAL, 0xFF6A2020)
    .setBackground(ButtonState.HOVER, 0xFF9A3030);
```

## What the server accepts

The client is untrusted, so the server checks every interaction before your callback runs:

- It must be for the screen the player has open.
- The widget must exist, be visible and be enabled.
- The action must match the widget, such as a click on a button or a slide on a slider.
- Text longer than the field's `maxLength` is dropped, and slider positions are clamped between 0 and 1.

## Players without the client

`openScreen` does nothing for players without the client mod. To offer them something else, check `isModded()` and use a command or a chest menu. See [players without the client](/plugin-development/players-without-the-client).

## Protocol

Clients that support popups report `ui.v1`.

| Channel | Direction | Contents |
|---|---|---|
| `spoutcraftredux:screen_open` | Server to client | The screen and all its widgets |
| `spoutcraftredux:screen_close` | Server to client | Close the open screen |
| `spoutcraftredux:widget_update` | Server to client | Added or changed widgets. Screen id 0 is the [HUD](/plugin-development/hud). |
| `spoutcraftredux:widget_remove` | Server to client | Removed widgets |
| `spoutcraftredux:control_event` | Client to server | `CLICK`, `CHECK`, `TEXT`, `SUBMIT`, `SLIDE` or `SELECT` |
| `spoutcraftredux:screen_closed` | Client to server | The player closed the screen |

Widgets travel as a generic description:
- **Common fields:** id, type, x, y, width, height, anchor, visible, enabled and tooltip JSON.
- **Properties:** a map of booleans, ints, floats, strings and string lists. Button styles use `texture`, `hover_texture` and `disabled_texture` (SHA-256), `background`, `hover_background` and `disabled_background`, `color`, `hover_color` and `disabled_color` (ARGB ints), `border` and `shadow`.
- **Type names:** `label`, `button`, `checkbox`, `text_field`, `slider`, `gradient`, `item`, `list` and `texture`.
- **Limits:** 1024 widgets per message and 32 properties per widget.
