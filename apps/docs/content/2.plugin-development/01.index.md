Plugins for SpoutCraft Redux are regular Paper plugins. They compile against `spoutcraftredux-api`, which is the full Purpur API (and therefore the Paper API) plus the `org.spoutcraftredux.api` package.

## Requirements

- **Java 25** toolchain
- A SpoutCraft Redux server for **26.3** to run the plugin on

## Add the dependency

The API is published to the SpoutCraft Redux Maven repository. Snapshots follow the `26.3-R0.1-SNAPSHOT` version scheme used by Paper and Purpur.

::code-group

```kotlin [build.gradle.kts]
plugins {
    java
}

repositories {
    mavenCentral()
    maven("https://repo.spoutcraftredux.org/snapshots")
}

dependencies {
    compileOnly("org.spoutcraftredux:spoutcraftredux-api:26.3-R0.1-SNAPSHOT")
}

java {
    toolchain.languageVersion = JavaLanguageVersion.of(25)
}
```

```xml [pom.xml]
<repositories>
    <repository>
        <id>spoutcraftredux-snapshots</id>
        <url>https://repo.spoutcraftredux.org/snapshots</url>
    </repository>
</repositories>

<dependencies>
    <dependency>
        <groupId>org.spoutcraftredux</groupId>
        <artifactId>spoutcraftredux-api</artifactId>
        <version>26.3-R0.1-SNAPSHOT</version>
        <scope>provided</scope>
    </dependency>
</dependencies>

<properties>
    <maven.compiler.release>25</maven.compiler.release>
</properties>
```

::

Use `compileOnly` (Gradle) or `provided` (Maven). The server already contains the API; never shade it into your plugin jar.

::note
`spoutcraftredux-api` replaces `paper-api` and `purpur-api` in your build. Remove those dependencies to avoid version conflicts.
::

## Declare the plugin

Both Paper plugin formats work. Set `api-version` to `26.3`.

::code-group

```yaml [paper-plugin.yml]
name: MyPlugin
version: 1.0.0
main: com.example.myplugin.MyPlugin
api-version: '26.3'
```

```yaml [plugin.yml]
name: MyPlugin
version: 1.0.0
main: com.example.myplugin.MyPlugin
api-version: '26.3'
```

::

Quote the version (`'26.3'`) so YAML reads it as a string and not a number.

## A first listener

This listener logs which players joined with the client mod:

```java [JoinListener.java]
package com.example.myplugin;

import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;
import org.spoutcraftredux.api.SpoutCraftReduxPlayer;
import org.spoutcraftredux.api.event.SpoutCraftReduxClientMissingEvent;
import org.spoutcraftredux.api.event.SpoutCraftReduxClientReadyEvent;

public final class JoinListener implements Listener {
    @EventHandler
    public void onReady(SpoutCraftReduxClientReadyEvent event) {
        SpoutCraftReduxPlayer player = event.getSpoutCraftReduxPlayer();
        event.getPlayer().sendMessage("SpoutCraft Redux " + player.modVersion().orElse("?") + " detected");
    }

    @EventHandler
    public void onMissing(SpoutCraftReduxClientMissingEvent event) {
        event.getPlayer().sendMessage("Install the SpoutCraft Redux client for the full experience.");
    }
}
```

Register it in `onEnable` with `getServer().getPluginManager().registerEvents(new JoinListener(), this)`.

## Supporting Paper and Purpur too

`player.spoutCraftRedux()` exists only on SpoutCraft Redux servers. If your plugin should also load on plain Paper or Purpur, check for the API before touching it and keep all SpoutCraft Redux calls in separate classes:

```java
boolean spoutCraftRedux;
try {
    Class.forName("org.spoutcraftredux.api.SpoutCraftReduxPlayer");
    spoutCraftRedux = true;
} catch (ClassNotFoundException e) {
    spoutCraftRedux = false;
}
```

## Coming from the original Spout

The API uses modern names instead of the old `SpoutPlayer`, `GenericButton` and `getSpoutPlayer()` classes, and widget text uses Adventure `Component`s. Most old concepts map directly: `SpoutPlayer` becomes [`SpoutCraftReduxPlayer`](/plugin-development/player-api), popups and HUD widgets become [GUIs](/plugin-development/guis) and [HUD](/plugin-development/hud) widgets, and movement multipliers become [movement](/plugin-development/movement) settings backed by vanilla attributes.
